Mixtral Healthcare LLM — From Scratch, Pretraining & Medical SFT

End-to-end PyTorch implementation of a Mixtral-style sparse Mixture-of-Experts language model: a healthcare-focused tokenizer, biomedical pretraining from randomly initialized weights, and full-parameter medical supervised fine-tuning. Explore the four-expert, top-2-routed decoder architecture, training checkpoints, evaluation workflow, and two separately hosted Hugging Face model releases.

PyTorchSparse MoEMedical SFTHugging Face

From-scratch architecture · healthcare pretraining · full-parameter SFT · research use

Read detailed technical overview ⌄

Sparse MoE language-model engineering

The implementation explores a custom decoder-only Transformer with rotary position encoding, grouped-query attention, normalization and a routed feed-forward path. A four-expert, top-two routing configuration illustrates how expert capacity and active computation can differ.

The two-stage lifecycle separates biomedical next-token pretraining from full-parameter medical instruction tuning. Review the training pipeline, checkpoint handling, documented evaluation scope and separate Hugging Face model cards; the release is for research and engineering, not medical decision-making.

Tenant-scoped retrieval design

This project examines retrieval as a service: API boundaries in FastAPI, vector retrieval backed by Qdrant, tenant-aware query scope and semantic caching. It is useful for understanding how retrieval infrastructure can be isolated by customer or tenant.

The documented output concerns retrieved context and retrieval behavior rather than a verified end-to-end answer-generation system. Explore how indexing, query isolation, cache reuse and service-level interfaces fit together.

Distributed LLM Training with PyTorch DDP

torchrun workers, DistributedSampler, gradient synchronization and Qwen LoRA training workflows with independent model replicas.

PyTorchDDPLoRA

Distributed training · torchrun

Read detailed technical overview ⌄

Distributed data-parallel training

PyTorch DistributedDataParallel synchronizes gradients across independently running model replicas. The code explores torchrun-based process launch, dataset sharding with DistributedSampler, gradient synchronization and training setup.

The project also discusses Qwen LoRA workflows, separating efficient parameter adaptation from the process-level mechanics of distributed training. It is an implementation reference, not a published throughput benchmark.

Batch inference and ordered outputs

This design demonstrates batch sentiment inference with Qwen2.5 using per-device model replicas, Python worker queues and JSONL input validation. Work can be partitioned across workers for parallel execution.

The pipeline tracks work items and reassembles results in input order, illustrating a practical difference between concurrent execution and deterministic output formatting. Review the repository for operational assumptions and execution instructions.

Transformer Encoder from Scratch

Custom multi-head self-attention, positional encoding, pre-LayerNorm blocks and classification on Yelp-style review data.

PyTorchAttentionNLP

Encoder architecture · classification

Read detailed technical overview ⌄

Transformer architecture foundations

A Transformer encoder is implemented around multi-head self-attention, positional encoding, residual connections and pre-layer normalization. The model is used for classification on review-like text.

Unlike a decoder-only generative language model, this architecture is an encoder-oriented representation model. The distinction is important when comparing training objectives, attention masks and downstream tasks.

Full-model versus frozen-backbone adaptation

The project compares updating DistilBERT encoder parameters with keeping the backbone frozen while training a classification component. The configurations help illustrate optimization flexibility and training-cost trade-offs.

Saved checkpoints, weighted F1 and confusion matrices provide a concrete evaluation workflow. Measured outcomes must be interpreted within the project dataset and configuration rather than generalized to all NLP tasks.

TECHNICAL CONTEXT / PROJECT GUIDE

From first-principles models to operational AI systems.

A focused explanation of the engineering areas represented across the linked repositories and Hugging Face checkpoints.

01 / FOUNDATIONS

Transformer and LLM architecture

The portfolio explores both decoder-oriented causal language modeling and encoder-oriented text classification. Example implementations cover tokenization, embeddings, self-attention, Transformer blocks and inference behavior. The custom healthcare MoE model adds expert routing and a two-stage pretraining/SFT workflow.

Healthcare MoE · Transformer encoder · Tiny GPT
02 / ADAPTATION

Pretraining, fine-tuning and evaluation

Projects distinguish random-weight pretraining, full-parameter adaptation, frozen-backbone comparisons, LoRA and preference-training techniques. The examples emphasize training objective, implementation constraints and evaluation outputs rather than unsupported claims of benchmark superiority.

Preference optimization · Fine-tuning comparison
03 / ORCHESTRATION

Retrieval, agents and MCP

Service-oriented retrieval uses vector search and tenant-scoped query boundaries. LangGraph examples demonstrate typed states, reducers and conditional flows; MCP-oriented market simulation shows how tool calls and protocol endpoints can be composed without real-world trade execution.

RAG service · LangGraph agents · MCP tooling
04 / SCALE

Distributed training and parallel inference

Parallelism appears in two separate contexts: distributed training replicas synchronizing gradients with PyTorch DDP, and inference workers producing ordered JSONL results. Both projects emphasize explicit workload distribution, output correctness and repeatable execution patterns.

Distributed DDP · Parallel inference
